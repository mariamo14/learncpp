solution: |
  #include <iostream>

  class Point2D {
  public:
      double x;
      double y;

      Point2D(double px, double py) : x(px), y(py) {
      }

      Point2D &operator+=(const Point2D &other) {
          x += other.x;
          y += other.y;
          return *this;
      }
  };

  int main() {
      double x1, y1, x2, y2;
      std::cin >> x1 >> y1 >> x2 >> y2;
      Point2D a(x1, y1);
      Point2D b(x2, y2);
      a += b;
      std::cout << "x = " << a.x << ", y = " << a.y << std::endl;
      return 0;
  }
---

Add `operator+=`, `operator+`'s compound cousin: instead of producing a new `Point2D`, it modifies `x` and `y` in
place and returns a reference to the same object it just changed.

Two details the lesson calls out as easy to get wrong: the return type is `Point2D &` (a reference to `*this`),
not `Point2D` (a new copy) and not `void` -- returning the wrong one compiles without complaint but breaks
chaining and wastes a copy, so it's worth writing `return *this;` as a fixed habit for every compound-assignment
operator you write from here on.
