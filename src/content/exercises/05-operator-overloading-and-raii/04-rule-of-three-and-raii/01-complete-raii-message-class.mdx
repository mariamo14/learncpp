solution: |
  #include <iostream>
  #include <string>
  #include <cstring>

  class Message {
  public:
      char *text;

      Message(const std::string &s) {
          text = new char[s.length() + 1];
          strcpy(text, s.c_str());
      }

      ~Message() {
          delete[] text;
      }

      Message(const Message &other) {
          text = new char[strlen(other.text) + 1];
          strcpy(text, other.text);
      }

      Message &operator=(const Message &other) {
          if (this == &other) {
              return *this;
          }
          delete[] text;
          text = new char[strlen(other.text) + 1];
          strcpy(text, other.text);
          return *this;
      }
  };

  int main() {
      std::string s;
      std::cin >> s;
      Message a(s);
      Message b = a;
      Message c(std::string("placeholder"));
      c = a;

      b.text[0] = 'X';

      std::cout << "a.text = " << a.text << std::endl;
      std::cout << "b.text = " << b.text << std::endl;
      std::cout << "c.text = " << c.text << std::endl;
      return 0;
  }
---

`Message` owns a `char *` -- a raw, manually-managed C-string, deliberately built the Module-2 way rather than
with `std::string`, so the Rule of Three genuinely applies. Add the destructor, copy constructor, and copy
assignment operator **together**, as one unit -- exactly the lesson's point, not three separate problems to solve
independently.

`main` exercises all three at once: `b` is created via the copy constructor, `c` is overwritten via copy
assignment, and every object is destroyed at the end whether it's `main`'s implicit return or the program simply
ending -- if any one of the three is wrong or missing, expect either wrong output (a mutation through `b` leaking
into `a` or `c`) or a crash.
