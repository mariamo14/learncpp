solution: |
  #include <stdio.h>

  int strings_equal(const char *a, const char *b) {
      int i = 0;
      while (a[i] != '\0' && b[i] != '\0') {
          if (a[i] != b[i]) {
              return 0;
          }
          i++;
      }
      return a[i] == '\0' && b[i] == '\0';
  }

  int main(void) {
      char a[100], b[100];
      scanf("%99s %99s", a, b);
      printf("%s\n", strings_equal(a, b) ? "Equal" : "Not equal");
      return 0;
  }
---

Implement string equality yourself, without calling `strcmp`. This is worth doing by hand once specifically
because the natural-looking wrong answer is subtle: it's not enough to compare characters until one string's
terminator shows up and declare victory if nothing mismatched along the way. `"cat"` and `"cats"` share every
character in `"cat"`'s length -- if your loop only checks for mismatches up to the shorter string's end, it'll
wrongly call them equal. The fix is checking, after the comparison loop, that **both** strings hit `'\0'` at the
exact same position -- if one is still going, they're different lengths, and can't be equal no matter how much of
a shared prefix they have.
