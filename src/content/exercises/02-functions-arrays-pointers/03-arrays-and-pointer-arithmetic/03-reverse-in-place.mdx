solution: |
  #include <stdio.h>

  void reverse(int *arr, int length) {
      int left = 0;
      int right = length - 1;
      while (left < right) {
          int temp = arr[left];
          arr[left] = arr[right];
          arr[right] = temp;
          left++;
          right--;
      }
  }

  int main(void) {
      int n;
      scanf("%d", &n);
      int values[100];
      for (int i = 0; i < n; i++) {
          scanf("%d", &values[i]);
      }

      reverse(values, n);

      for (int i = 0; i < n; i++) {
          printf("%d", values[i]);
          if (i < n - 1) printf(" ");
      }
      printf("\n");
      return 0;
  }

Implement `reverse` to reverse the array **in place** -- modify `arr` through its pointer directly, without
allocating a second array to copy into.

The standard technique is two indices (or, equivalently, two pointers) starting at opposite ends and walking
toward each other, swapping as they go, stopping once they meet or cross. This "converge from both ends" pattern
shows up again for palindrome checks, partitioning, and quicksort -- worth having solid here. Trace it by hand on a
4-element and a 5-element array before coding: does your stopping condition (`left < right`) correctly leave a
lone middle element alone in the odd case?
