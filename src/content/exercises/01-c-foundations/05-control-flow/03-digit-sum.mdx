  - "n % 10 gives you the last digit; n / 10 (integer division) drops it."
  - "Loop while n > 0, adding n % 10 to a running total and reassigning n = n / 10 each time."
  - "n = 0 is a special case worth tracing by hand: does your loop condition run zero times, and does that still give the right answer (0)?"
solution: |
  #include <stdio.h>

  int main(void) {
      int n;
      scanf("%d", &n);
      int sum = 0;
      while (n > 0) {
          sum += n % 10;
          n /= 10;
      }
      printf("Digit sum: %d\n", sum);
      return 0;
  }
---

Read a single non-negative integer `n` and print the sum of its decimal digits, in the form `Digit sum: 16`.

You're not allowed to treat the number as a string here -- pull digits off the *end* of the number using `% 10`
(remainder when dividing by 10 gives the last digit) and `/ 10` (integer division drops that digit), repeating
until nothing is left. This pattern -- peel off the low digit, shrink the number, repeat -- shows up constantly:
reversing a number, converting bases, checking for palindromes. Trace `n = 493` by hand before you code it: what are
`n`, `n % 10`, and `n / 10` after each iteration?
